# Contributing to Sparkle Validator

Thank you for your interest in contributing to Sparkle Validator! This document outlines the process for contributing to this project.

## Prerequisites

- **Node.js >= 22** is required (`node -v`).
- **npm >= 10**

## Development Setup

1. Fork and clone the repository:
   ```bash
   git clone https://github.com/dweekly/Sparkle-Validator.git
   cd Sparkle-Validator
   ```

2. Install dependencies:
   ```bash
   npm install
   ```

3. Run the development build:
   ```bash
   npm run dev
   ```

4. Run the test suite:
   ```bash
   npm test
   npm run test:xsd
   ```

## Project Structure

- `src/core/` - Shared validation engine (parser, rules, signature helpers, types). **Must remain pure browser-safe JavaScript/TypeScript** (no Node-only APIs like `fs`, `path`, `crypto`, or globals like `process`, `Buffer`).
- `src/cli/` - Command-line interface
- `src/web/` - Web application (HTML, CSS, UI client)
- `functions/` - Cloudflare Pages functions (SSRF-hardened fetch proxy)
- `test/` - Unit tests, integration tests, and XML fixtures
- `public/` - Built web app distribution (generated by `npm run build`)

## Adding New Validation Rules

1. Create or modify the appropriate rule file in `src/core/rules/`
2. Ensure every rule ID is **strictly unique** across all rule files
3. Register the rule in `src/core/rules/catalog.ts` and add documentation in `README.md`
4. Write comprehensive tests for the new rule in `test/core/rules/`
5. Add valid/invalid test fixtures in `test/fixtures/` if applicable

## Code Style and Quality Checks

- We use ESLint and Prettier for code consistency
- Check formatting: `npm run format:check` (or auto-format with `npm run format`)
- Check linting and TypeScript compilation: `npm run lint`

## Pull Request Process

1. Create a feature branch from `main`
2. Make your changes with clear, bisectable commits
3. Add or update tests covering new behavior and edge cases
4. Run all verification gates before submitting:
   ```bash
   npm run format:check
   npm run lint
   npm test
   npm run test:xsd
   npm run build
   ```
5. Submit a pull request with a clear description of changes

## Reporting Issues

When reporting issues, please include:
- A clear description of the problem
- Steps to reproduce
- The appcast.xml content (or a minimal reproduction)
- Expected vs actual behavior

## Code of Conduct

Please be respectful and constructive in all interactions. We aim to maintain a welcoming and inclusive environment for all contributors.
